# Дотестировать и доработать Zazor на реальном эмуляторе/устройстве

Это передаточный документ для сессии Claude Code, которая имеет доступ к
Android-эмулятору или физическому устройству через `adb`. Прочитай целиком
перед тем, как что-то запускать.

## Что это за приложение

Android-приложение для фиксации объектов на местности. Фотографирует и
наносит координаты, адрес, дату, время и точность GPS **прямо на
изображение**. Ключевое требование владельца: в самом файле снимка не
должно быть EXIF-метаданных устройства — координаты видны только на
картинке, а не в свойствах файла. Это проверяется командой `exiftool` на
реальном устройстве; симулятор для этой проверки не годится, потому что
подделывает GPS-фикс идеально и не даёт настоящей камеры.

## Стек

Kotlin, MVI, Koin DI, Room, CameraX, Gradle 8.14.5 / AGP 8.13.2 /
Kotlin 2.3.21. minSdk 24, targetSdk 36. 44 unit-теста, lint должен быть
чист (0 ошибок).

## Первый шаг — собрать и запустить

```
./gradlew testDebugUnitTest lintDebug   # должно быть зелёным без правок
./gradlew installDebug                  # поставить на эмулятор/устройство через adb
```

Для debug-сборки **не** нужен `keystore.properties` — используется
отладочный ключ автоматически. Команда генерации ключа для релиза и
сборка `bundleRelease` — в `RELEASE.md` в корне репозитория, это шаг
после тестирования, не раньше.

## Что обязательно проверить на живом устройстве

Симулятор годится для проверки вёрстки и переходов между экранами.
Пункты ниже требуют настоящую камеру и настоящий GPS-приёмник — на
эмуляторе они либо не воспроизводятся, либо врут.

1. **Съёмка → штамп с координатами** наносится на фото, лежит красиво,
   не обрезан ни на одном соотношении сторон экрана.
2. **Проверка метаданных.** Снять фото, вытащить файл (`adb pull`),
   прогнать через `exiftool`. `GPS*`, `Make`, `Model`,
   `DateTimeOriginal` должны отсутствовать полностью.
3. **Широкий угол / панорама.** CameraX выбирает сверхширокую линзу,
   если она есть на устройстве (Camera2 interop). Проверить на телефоне
   с 2–3 камерами.
4. **Предупреждение о слабом сигнале GPS.** Уйти в помещение с плохим
   приёмом, убедиться, что показывается диалог «Подождать / Снять как
   есть».
5. **Серия подхода.** Снять 2–3 кадра одного объекта с разной
   точностью, проверить, что для серии берётся кадр с лучшим fix, а не
   последний по времени.
6. **Голосовые заметки.** Запись, воспроизведение, что `MediaRecorder`
   не течёт при выходе из экрана во время записи.
7. **Массовое удаление в галерее.** Выделить несколько фото, удалить,
   проверить диалог подтверждения с правильным числом.
8. **Реклама (AdMob) в галерее.** Баннер должен грузиться один раз при
   заходе на экран и не перезагружаться при каждом возврате назад (был
   баг, починен коммитом «Stop the gallery banner reloading...») —
   проверить логами AdMob, что запрос не идёт при каждом `onResume`.
9. **Жест «назад»** (предиктивный, Android 13+) на всех экранах,
   включая открытую нижнюю шторку с заметкой.
10. **Экспорт GPX/KML.** Открыть файл в другом приложении (Google
    Earth / любой навигатор), убедиться, что координаты корректны.
11. **Код очистки** на экране входа должен стирать данные полностью.
12. **Смена значка приложения** (launcher alias) в настройках.
13. **Три языка.** Переключить системный язык на украинский и
    английский, проверить, что нет обрезанных строк в UI.
14. **Значок приложения на реальном лаунчере** — как выглядит в
    круглой/квадратной маске, в адаптивной иконке (Android 8+).

## Где что лежит в репозитории

- `RELEASE.md` — как собрать релиз, сгенерировать ключ подписи
- `docs/play-listing.md` — тексты для Google Play (описание,
  скриншоты, категории)
- `docs/privacy-policy.html` — политика конфиденциальности, готова к
  публикации

## Правило работы с багами

Нашёл баг → чинишь → коммит с понятным сообщением → `push` в `main`.
По договорённости с владельцем `main` — рабочая ветка, отдельный pull
request не нужен, пушить можно напрямую. После каждой правки — заново
прогнать `testDebugUnitTest` и `lintDebug` перед пушем.

## Контекст, которого здесь нет и который не нужен

История разработки, обсуждения дизайна, переписка с владельцем — не в
репозитории и не важны для тестирования. Весь нужный контекст — в коде,
в комментариях к коду (они объясняют «почему», а не только «что») и в
файлах, перечисленных выше.
